Component

Icon

One glyph source — lucide, 24×24 stroke icons with stroke="currentColor". The component only re-sizes (--icon-size-*), re-colors (semantic color tokens with matching hover/active pairs, plus inverse for dark surfaces via --on-dark) and re-weights (--stroke-width-icon) that source. Interactive icons live inside a native <button class="icon-btn">: keyboard focus and activation come for free. Every value below resolves from tokens.css — no raw hex, no arbitrary opacity.

Width always equals height; stroke weight stays --stroke-width-icon at every size, so smaller sizes read lighter automatically.

Every color has a matching hover/active pair in tokens.css — visible in the interactive section below, not on static glyphs. inverse resolves --on-dark and only reads on dark surfaces; on the light canvas it would be invisible.

.is-hover / .is-active / .is-focus force the state for this static page; in product markup the real :hover / :active / :focus-visible selectors drive the same tokens. Transitions use --duration-fast + --ease-standard and are removed under prefers-reduced-motion.

Accessibility — decorative vs meaningful

Decorative icons pair text and carry aria-hidden="true" — every icon on this page above is one. The two below stand alone:

role="img" + aria-label
announced by its label, not its shape

Interactive icons put the label on the native button, not the svg — screen readers announce "Delete document, button", never "trash glyph".
