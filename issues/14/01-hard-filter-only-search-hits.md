# 01 — 扩展检索契约：仅硬条件召回与命中论文摘要

**Parent:** GitHub Issue [#14](https://github.com/pray4her/relationship_network/issues/14) — `[MVP-13] 实现独立的自然语言人才搜索`

**What to build:** 服务端能用「硬条件和研究主题查询至少一项非空」从当前数据版本召回检索命中。仅有研究主题时仍做语义召回并按语义分降序；仅有硬条件时只做结构化过滤、不走向量、不含语义分，默认按 h-index 降序、同分按规范人物 ID。命中自带命中论文摘要（标题、年份、venue，可选 snippet）。自然语言原句、偏好条件和未支持条件仍不得进入检索底座。无租户界面，不扣额度。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 检索请求发送硬条件列表与研究主题查询，以及 1 至 500 的命中上限（默认 500）；硬条件与研究主题查询不可同时为空，否则 `invalid_query` 且不重试。
- [ ] 仅有研究主题、硬条件为空时允许语义召回；命中含有限数值语义分，同一次响应对语义分降序并共享同一数据版本。
- [ ] 仅有硬条件、研究主题查询为空时允许结构化召回；命中不含语义相关性信号；默认 h-index 降序，同分按规范人物 ID；不把语义分填 0。
- [ ] 硬条件字段与操作符仍与职位需求 Schema v1 目录一致；未知字段、未知操作符或非法华人身份取值得到 `invalid_query`，且不重试。
- [ ] 调用方传入偏好条件、未支持条件、职位原文或搜索原句时，适配器在发 HTTP 前拒绝。
- [ ] 检索命中含规范人物 ID、历史来源 ID、与详情相同的当前字段、可选联系方式标记，以及命中论文摘要（标题、年份、venue，可选 snippet）；不只返回论文 ID。
- [ ] 命中论文仍是该规范人物人物证据中的论文子集，不引入第二套论文身份。
- [ ] 检索命中不含完整联系方式，也不返回匹配算法版本下的总分或权重。
- [ ] 不调用、不封装检索底座现有的自然语言找专家能力；排序键不进入检索契约。
- [ ] 契约测试打真实适配器，覆盖：仅主题、仅硬条件、二者皆有、二者皆空、偏好条件预检拒绝、`invalid_query`、命中论文摘要、无主题时无语义分且顺序确定，以及至少一次经真实 HTTP 的集成检索。
- [ ] 假服务能按上述三种有效查询返回确定性命中，并能切换无效查询场景。
- [ ] 本切片不新增租户或平台管理 HTTP 路由、不创建自然语言搜索运行或匹配运行、不扣搜索额度。
