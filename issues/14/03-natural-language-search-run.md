# 03 — 自然语言搜索运行：从提交到结果、额度、失败重试与重开

**Parent:** GitHub Issue [#14](https://github.com/pray4her/relationship_network/issues/14) — `[MVP-13] 实现独立的自然语言人才搜索`

**What to build:** 具有 `search:run` 且租户可写的成员提交一句搜索原句后，同一次执行完成搜索解释并检索，形成不可变的自然语言搜索运行。结果页同时展示实际采用的硬条件与研究主题查询、不参与检索的未支持条件，以及搜索命中快照（本地人才、当时头部字段、命中论文摘要、可选语义分）。成功（含零命中）扣 1 次搜索额度；失败可恢复；可按约定键排序与分页；可重开当时快照并进入本地人才详情。联系方式始终脱敏。不是职位需求草稿，也不是匹配运行，也不是排队 SSE 任务。

**Blocked by:** 01 — 扩展检索契约：仅硬条件召回与命中论文摘要; 02 — 按调用类型绑定搜索解释提示词并探测全部类型; GitHub Issue [#13](https://github.com/pray4her/relationship_network/issues/13)

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 发起要求 `search:run` 与可写租户；查看本租户运行要求 `search:read`；所有者自动拥有二者；越权与过期只读租户均有允许/拒绝测试。
- [ ] 搜索原句经 NFC 与 LF 规范化后最长 4000 个 Unicode 字符；空、仅空白或超限返回稳定 400，不创建运行、不打 LLM、不打检索底座、不静默截断。
- [ ] 运行先落库，在请求内做完；超时或失败写成可恢复失败终态，不是排队中的解析任务，不提供职位需求解析那种 SSE 任务流。
- [ ] 搜索解释由当前 LLM 配置的搜索解释提示词与超时生成；硬条件与研究主题查询同时为空则解释无效；未支持条件展示为不参与检索，不创建人工核实任务；用户不能在检索前修改条件。
- [ ] 解释有效后才预占 1 次 `searches`；检索底座成功（含零命中）确认；解释无效不记账；底座失败或超时释放预占。
- [ ] 成功命中对每条检索命中 get-or-create 本地人才，并冻结搜索命中快照（本地人才 ID、当时头部字段、数据版本、命中论文摘要、可选语义分）；失败运行与零命中不同步人才。
- [ ] 召回上限 500；结果表默认每页 50；展示层可按姓名、当前机构、国家、华人身份、h-index、总引用、QS 排名、世界排名改排，作用于本次运行已返回的全部命中；无主题时默认 h-index 降序；有主题时默认语义分降序，改排后标明已离开相关性次序。排序键不发给检索底座。
- [ ] 重开运行展示冻结快照；点进人才详情展示本地人才最新头部字段。结果不含完整联系方式，最多展示是否有联系方式；本切片不解锁。
- [ ] 客户端幂等键指纹为规范化原句 + LLM 配置版本 + 检索契约版本；同键同指纹永远回原运行；同键不同指纹 409；失败终态同键只回放不重跑；显式重试创建新运行和新键，成功才再扣 1 次。
- [ ] 技术限流默认同时 1 个请求内执行、每小时新建 20（可配）；解释失败也计入；重复幂等键不计；超限 429，不落新运行、不打 LLM、不打检索底座。
- [ ] 已认证写路径的成功与业务拒绝写入不含原句全文或完整 JSONB 的租户审计事件；普通读取不记。
- [ ] 后端、RLS、用量账本、前端契约/组件和浏览器测试覆盖：成功有命中、零命中、仅硬条件、仅主题、未支持条件展示、解释失败不扣费、底座失败可恢复并重试为新运行、额度不足、幂等回放、指纹冲突、技术限流、空/超限原句、越权、跨租户隔离、排序分页与重开快照。迁移支持 upgrade → downgrade → upgrade。
