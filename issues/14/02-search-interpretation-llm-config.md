# 02 — 按调用类型绑定搜索解释提示词并探测全部类型

**Parent:** GitHub Issue [#14](https://github.com/pray4her/relationship_network/issues/14) — `[MVP-13] 实现独立的自然语言人才搜索`

**What to build:** 平台管理员可以在同一不可变 LLM 配置版本上，为职位需求解析和搜索解释各绑定一条提示词版本和超时。搜索解释使用独立的不可变提示词资产与结构化输出契约（硬条件、可空研究主题查询、未支持条件；无偏好条件、无来源冲突；字段目录声明兼容的职位需求 Schema 版本）。最小能力探测必须覆盖所声明的全部调用类型，全部通过才启用新配置版本；任一种失败则整个配置变更尝试失败。模型和隐私路由仍共享，ZDR 等强制约束不变。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 仓库新增搜索解释提示词版本与严格 JSON Schema 资产，带稳定标识和内容哈希；提示词声明唯一兼容的职位需求 Schema 版本；CI 能识别哈希漂移。
- [ ] 搜索解释输出只含硬条件、研究主题查询与未支持条件；研究主题查询允许为空；硬条件与研究主题查询不可同时为空；目录内能执行的条件一律为硬条件；没有偏好条件和来源冲突。
- [ ] LLM 配置版本按调用类型绑定提示词与超时；模型和隐私路由仍只发布一次。历史配置复制后再探测，不直接重启用旧记录。
- [ ] 职位需求解析超时仍为 30 至 300 秒（默认 180 秒）；搜索解释超时为 5 至 30 秒（默认 15 秒）；白名单生成参数范围不因此放宽隐私或跨模型回退。
- [ ] 平台管理员在现有平台管理员身份与强制 MFA 下可选择已部署的搜索解释提示词并设置其超时；普通租户成员不能读取或修改平台配置。
- [ ] 最小能力探测对配置版本声明的每一种调用类型各做一次严格结构化探测；全部通过才在同一事务中创建并启用新配置版本。
- [ ] 搜索解释探测失败时整个配置变更尝试失败，不启用新版本；已发出的探测调用记录和平台审计事实保留。
- [ ] 探测仍使用固定、非业务数据和强制 ZDR 路由；不要求回归评估，不计入租户额度或租户技术限流。
- [ ] 租户职位需求解析继续使用配置版本中该调用类型的提示词与超时，行为不因新增搜索解释绑定而静默改变。
- [ ] 后端、配置探测集成、前端管理界面与权限拒绝测试覆盖：双类型探测成功、搜索解释探测失败导致不启用、超时范围校验、历史复制后重探测。
- [ ] 本切片不新增租户搜索界面、不创建自然语言搜索运行、不调用检索底座、不扣搜索额度。
