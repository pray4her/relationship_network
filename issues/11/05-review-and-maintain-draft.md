# 05 — 审阅和维护职位需求草稿

**Parent:** GitHub Issue [#11](https://github.com/pray4her/relationship_network/issues/11) — `[MVP-10] 接入 OpenRouter 并完成职位需求解析确认`

**What to build:** 成员可以在职位详情中完整审阅和修改职位需求草稿，解决来源冲突，保留模型提取与人工修改事实，并通过乐观并发控制避免成员之间静默覆盖。重新解析期间旧草稿只读；成功时原子替换，失败或取消时恢复原草稿。

**Blocked by:** 04 — 可靠执行并实时展示职位需求解析任务.

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 数据库强制每个职位最多一份可编辑职位需求草稿，并保留 `editable`、`confirmed`、`replaced`、`abandoned` 的长期生命周期事实。
- [ ] 草稿以通过其绑定 Schema 整体校验的 JSONB 快照保存，同时使用关系列保存租户、职位、草稿身份、revision、来源任务和时间。
- [ ] 编辑器以扁平列表分别展示硬条件和偏好条件，并提供与字段匹配的正向操作符；同字段多值使用 `in`，不开放跨字段 OR、NOT、排除、前缀或存在性操作符。
- [ ] 华人身份使用“华人身份”产品标签和国内华人、海外华人、外国人值，不展示推断来源、推断理由或可能误判提示。
- [ ] 研究主题查询保持单一、可编辑且非空，并明确用于语义检索；模型和编辑器都不为偏好条件生成候选评分。
- [ ] 未支持条件可以编辑或移除，不参与执行、不阻止确认，也不要求逐项确认。
- [ ] 模型识别的来源冲突不能由模型自动解决；每个未解决冲突阻止确认，成员的处理方式、成员和时间保存在草稿及后续版本中。
- [ ] 成员可以增加、修改或删除条件；人工新增项明确标记为用户添加，不伪造模型证据。
- [ ] 修改模型提取值时保留原值和原始证据，同时记录新值、修改成员和时间，不要求填写修改原因。
- [ ] 草稿保存、放弃和后续确认都要求预期 revision；过期 revision 返回明确冲突并返回或允许重新取得当前状态，不能覆盖较新修改。
- [ ] 非终态重新解析任务存在时旧草稿只读；任务成功时在一个事务中标记旧草稿为已替换并创建新草稿，失败或取消时恢复旧草稿编辑能力。
- [ ] 成员可以在没有非终态替换任务时放弃草稿；放弃不改变职位当前需求版本，也不删除草稿历史。
- [ ] `draft`、`active`、`closed` 职位允许编辑，`archived` 职位只能查看；写操作要求 `jobs:manage` 与可写租户门禁，读取要求 `jobs:read`。
- [ ] 成功编辑、放弃、冲突和业务状态拒绝均写入不含完整草稿内容的租户审计事件；RLS 隐藏的跨租户探测不泄露目标事实。
- [ ] 测试覆盖所有字段/操作符、默认偏好、研究主题、证据保留、未支持条件、来源冲突、revision 冲突、替换成功/失败/取消、放弃和归档只读。
