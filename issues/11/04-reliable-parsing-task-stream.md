# 04 — 可靠执行并实时展示职位需求解析任务

**Parent:** GitHub Issue [#11](https://github.com/pray4her/relationship_network/issues/11) — `[MVP-10] 接入 OpenRouter 并完成职位需求解析确认`

**What to build:** 职位需求解析任务在浏览器断线、Worker 崩溃、消息重复、上游限流和取消竞态下仍以 PostgreSQL 状态为事实源可靠推进。成员通过单任务 SSE 查看排队、执行、等待重试、取消和终态，并能够取消任务；职位归档始终优先且迟到结果不能改变业务草稿。

**Blocked by:** 03 — 从职位描述和职位材料生成职位需求草稿.

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 数据库强制任务状态只能在 `queued`、`running`、`retry_scheduled`、`cancel_requested`、`succeeded`、`failed`、`cancelled` 的允许边上转换，并强制租约令牌、终态不可逆和同职位最多一个非终态任务。
- [ ] 租户范围幂等键绑定完整有效请求指纹；相同键和指纹返回原任务，不同指纹返回 `idempotency_conflict`，且不创建快照、任务、Outbox、调用记录或限流计数。
- [ ] 默认每租户最多两个 `running` 任务和每小时二十个新任务；队列与等待重试不占执行槽位，技术限流返回 HTTP 429 且没有业务副作用。
- [ ] Outbox Dispatcher 使用独立受限数据库角色和固定批量领取函数，只得到最小租户、任务和事件标识，不能任意跨租户查询业务表。
- [ ] Celery 至少一次投递不会重复创建调用或草稿；Worker 通过行锁、租约和心跳领取任务，租约过期只重新排队同一任务。
- [ ] `retry_scheduled` 和 `next_attempt_at` 是重试事实源；数据库调度器到期后原子重新排队并写入 Outbox，不以 Celery ETA 保存业务真相。
- [ ] 网络错误、超时、429 和上游 5xx 可重试，并优先遵守 `Retry-After`，否则使用带抖动指数退避；永久认证、余额、参数、隐私路由或配置错误立即失败。
- [ ] 每任务最多三次实际 OpenRouter 请求，结构无效最多两次；`outcome_unknown` 计入同一预算，后续尝试创建新的调用记录。
- [ ] 只有持有有效租约并成功完成原子状态转换的 Worker 可以创建或替换草稿；重复、迟到或取消后的响应只保留为 LLM 调用事实。
- [ ] `jobs:manage` 且租户可写的成员可以幂等取消排队、执行中或等待重试任务；已有草稿保持不变，新任务只能在旧任务进入取消终态后创建。
- [ ] 归档事务立即使职位只读，并将排队或等待重试任务取消、执行中任务转为取消中；归档后的任何外部结果不得创建或替换草稿。
- [ ] 每次业务状态变化在同一事务中写入从 1 连续递增的只增任务事件；事件仅包含租户可见状态、稳定错误分类、可重试性和下次尝试时间。
- [ ] SSE 按单个任务授权，要求 `jobs:read`，通过当前会话和 RLS 读取持久事件；PostgreSQL NOTIFY 只负责唤醒，不承载事件正文。
- [ ] SSE 支持 `Last-Event-ID` 补读、15 秒非持久心跳、60 秒正常关闭并重新认证，以及终态事件后立即关闭；断线和 NOTIFY 丢失不会丢业务事件。
- [ ] 真实 PostgreSQL/Redis 集成测试覆盖 Outbox 恢复、重复投递、租约过期、计划重试、限流、取消竞态、归档竞态、未知结果、迟到响应和恰好一个草稿提交。
- [ ] 前端和浏览器测试覆盖 SSE 重连、页面刷新恢复、权限变化、稳定错误、取消和归档只读体验。
