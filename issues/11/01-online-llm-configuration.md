# 01 — 在线管理并启用 LLM 配置版本

**Parent:** GitHub Issue [#11](https://github.com/pray4her/relationship_network/issues/11) — `[MVP-10] 接入 OpenRouter 并完成职位需求解析确认`

**What to build:** 平台管理员可以查看不可变的职位需求 Schema、提示词和 LLM 配置历史，在线提交一组候选配置，并在持久化异步最小能力探测成功后立即启用新的 LLM 配置版本。探测失败、取消或并发冲突不得创建配置版本；恢复历史配置必须复制后重新探测并创建新版本。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 迁移创建不可变的职位需求 Schema、提示词版本、LLM 配置版本、LLM 配置变更尝试及其事件，并初始化使用 `x-ai/grok-4.5` 的当前配置。
- [ ] 职位需求 Schema v1 冻结固定可执行条件目录、正向操作符、严格 JSON Schema、业务校验规则和输出上限；提示词版本声明且只声明一个兼容的 Schema 版本。
- [ ] 已被配置引用的提示词资产使用稳定标识和哈希，不可在线编辑或删除；CI 能识别资产内容与声明哈希不一致。
- [ ] 平台管理员可在现有平台管理员身份与全局 MFA 门禁下查看当前配置及不可变历史；普通租户成员不能读取平台配置。
- [ ] 在线可编辑项仅包括模型、已部署提示词和允许的生成参数：`temperature`、`max_output_tokens`、`request_timeout_seconds`，且参数范围与默认值符合父规格。
- [ ] 适配器固定使用非流式请求，并强制 ZDR、拒绝数据收集、必需参数支持和禁止跨模型回退；只允许在满足约束的上游提供方之间进行同模型路由。
- [ ] 配置提交携带预期当前版本，成功创建持久化异步尝试并返回 HTTP 202；候选配置以不含部署密钥的只读 JSONB 快照保留。
- [ ] 数据库强制全平台最多一个非终态配置变更尝试；重复提交返回稳定的 `config_change_in_progress` 冲突和现有尝试标识。
- [ ] 最小探测使用固定、非业务数据和严格 Schema，通过事务型 Outbox、Worker、租约、心跳及持久重试计划执行；探测不要求回归评估记录或单独发布动作。
- [ ] 探测最多产生三次实际 OpenRouter 调用，其中结构无效最多两次；网络、超时、429 和 5xx 按规则重试，永久配置或隐私约束错误立即失败。
- [ ] 探测成功时在一个事务中创建不可变配置版本并切换当前版本；失败、取消、迟到响应或当前版本已变化时不创建版本。
- [ ] 平台管理员可以取消非终态尝试；复制历史配置会创建新的候选尝试，探测成功后形成引用来源版本的新配置版本，而不是重新启用旧记录。
- [ ] 配置尝试提供单尝试 SSE，支持连续事件编号、`Last-Event-ID` 恢复、15 秒心跳、60 秒重认证以及终态后关闭。
- [ ] 后端、真实 PostgreSQL/Redis 集成、前端契约与组件测试覆盖成功、失败、重试、取消、并发冲突、回滚和权限拒绝；迁移支持 upgrade → downgrade → upgrade。
