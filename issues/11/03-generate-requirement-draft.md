# 03 — 从职位描述和职位材料生成职位需求草稿

**Parent:** GitHub Issue [#11](https://github.com/pray4her/relationship_network/issues/11) — `[MVP-10] 接入 OpenRouter 并完成职位需求解析确认`

**What to build:** 具有 `jobs:manage` 权限的成员可以在职位详情中按来源选择职位描述和职位材料、修正提取文本并提交冻结的职位需求输入快照。系统异步调用当前 LLM 配置，在严格结构、业务规则和来源证据校验全部通过后生成一份可查看的职位需求草稿。

**Blocked by:** GitHub Issue #10; 01 — 在线管理并启用 LLM 配置版本; 02 — 记录、诊断并清理 LLM 调用数据.

**Status:** ready-for-agent

## Acceptance criteria

- [ ] `draft`、`active` 和 `closed` 职位允许发起解析；`archived` 职位严格只读。创建任务要求 `jobs:manage` 和现有可写租户门禁，查看要求 `jobs:read`。
- [ ] 职位详情按来源分别展示职位描述和每份可选职位材料，不提供失去来源映射的合并编辑框。
- [ ] 被选职位材料必须在当前 RLS 租户内属于同一职位且状态为 `content_checked`；空提取文本必须先填写非空修正文案才能选中。
- [ ] 每个来源分段保留稳定来源标识、原始文本、成员修正文案、编辑成员与时间、原始来源哈希、发送内容哈希、Unicode 字符长度和确定性顺序，不要求填写修改原因。
- [ ] 发送内容只进行 Unicode NFC 和 LF 换行规范化，不折叠空白、不忽略大小写、不改写标点。
- [ ] 输入快照至少有一个非空来源，默认总长度上限为当前 LLM 配置冻结的 100,000 个 Unicode 字符；超限时拒绝提交，不截断也不自动摘要。
- [ ] 提交在一个事务中创建不可变输入快照、职位需求解析任务、首个只增业务事件和 Outbox 事件，并返回 HTTP 202。
- [ ] Worker 使用普通应用数据库角色，按消息中的租户和任务标识设置 `app.tenant_id` 并在 RLS 下读取业务数据。
- [ ] OpenRouter 输出必须通过任务绑定的严格 JSON Schema、业务校验和输出上限；未知字段、超限输出或无效证据使整次输出无效，不能生成草稿。
- [ ] 固定可执行条件目录包括排名、华人身份、国家、当前任职机构、h-index 和总引用数，并只接受父规格规定的正向操作符与扁平 AND 语义。
- [ ] 模型提取的可执行条件、未支持条件和来源冲突都包含可验证来源、Unicode 字符偏移和精确引文；偏移对应的规范化子串必须与引文完全相等。
- [ ] 研究方向始终形成且只形成一个非空研究主题查询，用于后续语义检索，不转换为硬条件；强度不明确的条件默认归为偏好条件。
- [ ] 结构化结果成功时创建一份通过完整 Schema 校验的 JSONB 职位需求草稿；失败任务不留下部分草稿或部分结构化输出。
- [ ] 页面刷新后可以从持久化任务状态恢复当前任务和终态草稿；租户界面只显示稳定业务错误，不暴露供应商诊断、账户信息、成本或原始响应。
- [ ] 解析不写入租户用量台账，也不消耗匹配额度；所有成功写入和已认证业务拒绝写入不含完整业务正文的租户审计事件。
- [ ] 后端、RLS、前端契约/组件和浏览器测试覆盖描述单来源、材料多来源、修正空文本、超限、跨租户材料、证据无效、Schema 无效、成功草稿和权限拒绝。
