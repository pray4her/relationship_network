# 02 — 记录、诊断并清理 LLM 调用数据

**Parent:** GitHub Issue [#11](https://github.com/pray4her/relationship_network/issues/11) — `[MVP-10] 接入 OpenRouter 并完成职位需求解析确认`

**What to build:** 每次实际 OpenRouter 请求在发出前形成独立、不可覆盖的 LLM 调用记录，结果、迟到元数据和加密原始响应按不同生命周期分层保存。平台管理员可以在现有 MFA 门禁下诊断调用并留下操作记录，租户成员不能取得原始响应；到期密文只能通过受限维护路径删除。

**Blocked by:** 01 — 在线管理并启用 LLM 配置版本.

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 配置探测和租户职位需求解析共用统一的 LLM 调用记录，但数据库以 `platform`、`tenant` scope 及必需关联标识强制区分两者。
- [ ] 每次实际外部请求在发送前插入一条独立调用核心记录；自动重试、结果不确定后的再次尝试和配置探测都不能合并记录。
- [ ] 调用核心只保存输入快照引用、来源摘要、哈希、长度、提示词/Schema/配置版本、生成参数和提供方请求标识，不保存完整消息、组装提示词或请求正文。
- [ ] 调用结果使用只增事件表达 `succeeded`、`failed`、`outcome_unknown` 和 `late_response`；数据库强制只有一个初始结果，并只允许在未知结果之后追加迟到响应。
- [ ] Token、成本和实际上游提供方使用只增元数据事件补齐；元数据延迟、缺失或查询失败不能改变已成功的职位需求草稿或配置版本。
- [ ] 完整原始响应和无效结构化响应使用应用层 AES-GCM 加密，记录密钥版本和 90 天到期时间；密钥环及活动密钥标识仅通过 `RN_` 环境配置提供。
- [ ] 旧密钥保留到所有关联密文到期；缺失历史密钥只产生平台诊断，不回滚或重跑已经完成的业务结果。
- [ ] 平台管理员在现有全局 MFA 门禁下可以查看原始响应，无需逐次填写原因或再次完成 MFA；每次查看都写入平台审计事件。
- [ ] 租户成员无法读取原始响应的明文或密文，也无法通过空租户标识访问平台调用；子表直接执行与父调用一致的 scope/RLS 约束。
- [ ] 普通 API 和 Worker 角色对调用核心、结果事件和元数据事件只有 SELECT/INSERT 权限，不得更新或删除。
- [ ] 独立维护数据库角色只能执行固定到期清理函数，且函数只能删除已到期原始响应；普通应用和 Worker 没有原始响应 DELETE 权限。
- [ ] 调用核心、结果事件和元数据事件长期保留；原始响应到期清理不会删除调用身份、结果或成本事实。
- [ ] 测试覆盖一请求一记录、失败尝试保留、未知结果与迟到响应、延迟元数据、scope 隔离、加密与密钥轮换、管理员查看审计和受限清理权限。
