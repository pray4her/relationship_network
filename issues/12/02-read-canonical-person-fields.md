# 02 — 按规范人物读取当前字段（详情与批量）

**Parent:** GitHub Issue [#12](https://github.com/pray4her/relationship_network/issues/12) — `[MVP-11] 建立检索底座版本化内部服务契约`

**What to build:** 服务端能按规范人物 ID 读取当前数据版本下的人物当前字段（含历史来源 ID 与可选联系方式标记），也能一次批量读取最多 500 人。当前数据版本中不存在的 ID 以当前缺失返回：详情不编造空人，批量对其余 ID 仍然成功。任何成功读取都不含完整联系方式。

**Blocked by:** 01 — 接通检索底座：服务认证、契约版本、健康检查与假服务

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 详情按规范人物 ID 返回当前数据版本、显示名、当前机构、国家、华人身份、H-index、总引用、可选机构排名、历史来源 ID，以及可选「是否存在可解锁联系方式」标记。
- [ ] 华人身份取值仅限国内华人、海外华人、外国人，并视为检索底座推断分类，不表述为国籍或民族。
- [ ] 详情与批量成功响应必须带数据版本与回显的请求标识；缺任一字段视为 `invalid_response`。
- [ ] 成功载荷不含邮箱、电话或其他完整联系方式；日志亦不记录这些值。
- [ ] 单 ID 在当前数据版本中不存在时返回当前缺失，不合成空的规范人物；底座不区分从未存在与业已消失。
- [ ] 批量最多 500 个规范人物 ID；超出上限在发 HTTP 前被拒绝。
- [ ] 批量成功时返回已找到的人与当前缺失 ID 列表；当前缺失不是错误类别。
- [ ] 认证失败、超时、5xx 或契约不兼容使整批失败，不得把传输失败伪装成部分成功。
- [ ] 一次成功读取中的人物同属一个数据版本；契约不提供按历史数据版本回查。
- [ ] 契约测试打真实适配器；假服务提供至少一名可命中人物、一个当前缺失 ID，以及认证/传输失败场景。
- [ ] 不新增租户路由、不落本地人才、不扣额度。
