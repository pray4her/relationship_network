# 03 — 读取人物证据

**Parent:** GitHub Issue [#12](https://github.com/pray4her/relationship_network/issues/12) — `[MVP-11] 建立检索底座版本化内部服务契约`

**What to build:** 服务端能按规范人物 ID 读取当前数据版本下的人物证据：论文与结构化字段出处主张。该读取不依赖某次检索或研究主题查询，也不含完整联系方式。当前缺失语义与详情一致。

**Blocked by:** 02 — 按规范人物读取当前字段（详情与批量）

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 人物证据按规范人物 ID 读取，不接受检索查询、硬条件或研究主题查询作为入参。
- [ ] 成功结果包含当前数据版本、论文（稳定论文 ID、标题、年份、Venue、可选摘录）以及不含联系方式取值的结构化字段出处。
- [ ] 成功载荷不含邮箱、电话或其他完整联系方式。
- [ ] 人物证据不是职位需求解析中的来源摘录，也不回答「为何命中某次检索」。
- [ ] 当前数据版本中不存在的 ID 返回当前缺失，不合成空证据档。
- [ ] 成功响应回显请求标识并携带数据版本；缺字段视为 `invalid_response`。
- [ ] 同一规范人物的详情与人物证据属于同一当前数据版本。
- [ ] 契约测试打真实适配器；假服务为已播种规范人物提供确定性论文与字段出处。
- [ ] 不新增租户路由、不落快照、不扣额度、不提供完整联系方式读取。
