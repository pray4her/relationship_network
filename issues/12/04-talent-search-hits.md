# 04 — 人才检索：硬条件与研究主题查询返回检索命中

**Parent:** GitHub Issue [#12](https://github.com/pray4her/relationship_network/issues/12) — `[MVP-11] 建立检索底座版本化内部服务契约`

**What to build:** 服务端能用硬条件与非空研究主题查询从当前数据版本召回检索命中：规范人物当前字段、命中论文与语义相关性信号。偏好条件不得进入检索底座；目录外字段失败为无效查询。命中按语义分排序、最多 500 条，不含匹配总分与完整联系方式；命中论文是该人物证据中的论文子集。不调用检索底座的自然语言找专家接口。

**Blocked by:** 02 — 按规范人物读取当前字段（详情与批量）；03 — 读取人物证据

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 检索请求只发送硬条件列表（可为空）与非空研究主题查询，以及 1 至 500 的命中上限（默认 500）。
- [ ] 硬条件字段与操作符与职位需求 Schema v1 目录一致：机构排名/H-index/总引用为 `gte`/`lte`/`between`，华人身份/国家为 `eq`/`in`，当前机构为 `match`/`match_phrase`；条件之间为扁平 AND。
- [ ] 调用方传入偏好条件、未支持条件、职位原文或用户原句时，适配器在发 HTTP 前拒绝。
- [ ] 研究主题查询缺失或为空时拒绝检索；仅有研究主题、硬条件为空时允许召回。
- [ ] 未知字段、未知操作符或非法华人身份取值得到 `invalid_query`，且不重试。
- [ ] 检索命中含规范人物 ID、历史来源 ID、与详情相同的当前字段、可选联系方式标记、命中论文 ID 与有限数值语义分；同一次响应对语义分降序排列并共享同一数据版本。
- [ ] 命中论文 ID 均能在该规范人物的人物证据中找到，不引入第二套论文身份。
- [ ] 检索命中不含完整联系方式，也不返回匹配算法版本下的总分或 50/20/20/10 权重。
- [ ] 不调用、不封装检索底座现有的自然语言找专家能力。
- [ ] 契约测试打真实适配器，覆盖命中、空硬条件、偏好条件预检拒绝、`invalid_query`、上限越界、无联系方式，以及至少一次经真实 HTTP 的集成检索。
- [ ] 假服务按硬条件与研究主题查询返回确定性命中，并能切换无效查询场景。
- [ ] 本切片不新增租户搜索界面、不创建匹配运行、不扣搜索或匹配额度。
