# 可执行条件使用固定的类型化目录

职位需求草稿与职位需求版本中的可执行条件只能使用平台预定义的类型化字段和操作符，模型识别出的目录外条件必须进入未支持条件列表；未知字段或操作符出现在可执行条件中时，整个结构化响应无效。相较于接受任意模型生成的筛选 JSON，固定目录让解析能力与检索底座的真实能力保持一致，避免界面声称执行了系统无法兑现的条件，并为后续目录版本化和回归测试提供稳定契约。

首期可执行条件采用扁平列表，列表中的条件全部同时满足；同一字段的多个允许值通过 `in` 表达，不支持跨字段嵌套 `OR` 或 `NOT`。不能无损转换为这一结构的复杂布尔逻辑进入未支持条件，而不直接保存或暴露 CombineDatabase 的底层查询树。

可执行条件分为硬条件与偏好条件：硬条件不满足时排除人才，偏好条件不影响召回，仅参与后续确定性评分。模型根据职位材料中的强制或偏好措辞作出初步分类，用户可在确认职位需求版本前调整分类；LLM 不直接决定候选人得分。

职位材料提到目录内条件但没有明确的强制或偏好措辞时，默认归为偏好条件。用户必须显式确认或调整后才能形成职位需求版本，避免模型把模糊表述擅自升级为会排除候选人的硬条件。

研究方向、技术主题和领域关键词不进入可执行条件目录，而是形成可编辑的研究主题查询，通过论文向量召回与相关性评分执行。即使职位材料使用强制措辞，也不把缺少可靠结构化人员字段支持的研究主题伪装成硬过滤条件。

每个职位需求草稿和职位需求版本恰好包含一条非空研究主题查询。多个研究主题由模型组合为一条可编辑查询；用户可以修改但不能清空后确认，以保持与检索底座单一 `vector_query` 契约一致。

未支持条件保留在职位需求草稿与版本中并明确标示不参与匹配，用户可以编辑或删除；它们不阻止确认，也不要求逐项勾选确认，不产生人工复核任务。用户对整个职位需求版本的确认即为知情边界。

模型提取的硬条件、偏好条件、未支持条件和来源冲突必须携带输入分段来源 ID 与原文摘录，后端验证摘录确实存在于对应职位需求输入快照分段；引用缺失或不匹配时整个结构化响应无效。用户手工新增的条件明确标记为用户新增，不伪造模型来源证据。

每条模型来源证据具体包含 `source_id`、`start_offset`、`end_offset` 和 `quote`。偏移以 NFC、`LF` 规范化后的来源分段 Unicode 字符为单位，后端必须验证 `normalized_text[start_offset:end_offset] == quote`；不执行模糊匹配、空白折叠或大小写忽略。偏移越界或摘录不一致时整个结构化响应无效。

用户修改或删除模型提取的条件时，保留原始值和模型来源证据，并记录新值、操作成员与时间；最终条件标记为用户修改。正常校正不要求填写修改原因，但不得覆盖或伪装原始模型结果。

字段目录、每个字段允许的操作符、结构化 JSON Schema 和业务校验规则作为一个不可变的职位需求 Schema 版本共同发布。提示词版本引用一个 Schema 版本，每个解析任务、职位需求草稿和职位需求版本都记录该版本，避免提示词、模型输出和后端校验规则独立漂移。

每个提示词版本必须在部署清单中声明唯一兼容的职位需求 Schema 版本。提示词内容、发送给 OpenRouter 的严格 JSON Schema 与应用业务校验器必须解析到同一版本；任何不匹配组合都不得进入配置探测或解析执行。

职位需求 Schema v1 只开放正向操作符：机构排名、H-index 和总引用量使用 `gte`、`lte` 或 `between`；华人身份和国家使用 `eq` 或 `in`；当前机构使用 `match` 或 `match_phrase`。否定、排除、前缀和字段存在性诉求进入未支持条件，不进入扁平 AND 可执行条件列表。

职位需求 Schema v1 同时冻结输出规模上限：硬条件、偏好条件与未支持条件合计最多 100 项，来源冲突最多 50 项，研究主题查询最多 4,000 个 Unicode 字符，单条条件说明或来源摘录最多 2,000 个字符。任何超限响应整体视为结构无效并进入既定重试预算，系统不得静默截断；这些上限不能通过在线 LLM 配置修改。

未来出现新 Schema 时，基于历史职位需求版本手工创建的草稿默认继续使用原 Schema；只有用户显式执行 Schema 升级并检查转换结果后才切换，不自动改变历史语义。新的 OpenRouter 解析任务始终绑定操作时的当前 Schema 版本。

用于新解析任务的当前 Schema 不维护独立数据库指针，而是由当前 LLM 配置所选提示词声明的兼容 Schema 版本派生。配置版本原子绑定模型、提示词和 Schema；当前配置切换后新任务使用新组合，已经创建的任务、草稿和职位需求版本继续保留其原组合。

用户显式升级历史职位需求草稿时，只能运行仓库内按起止 Schema 版本登记的确定性转换器，不调用 LLM 重新解释历史语义。转换保留升级前 JSONB 快照、原来源证据和逐字段映射结果；任何无法无损转换的内容进入待人工解决列表，在全部解决前禁止确认职位需求版本。
