# 职位需求内容保存为 Schema 校验的 JSONB 快照

职位需求草稿和确认版本使用关系型列保存租户、职位、版本号、Schema 版本、创建者和时间等身份与关联字段，硬条件、偏好条件、研究主题查询、未支持条件、来源证据和冲突解决记录则保存为经过对应职位需求 Schema 验证的整体 JSONB 快照。相比为每种条件拆分多张关系表，这一结构更适合不可变、多态且随 Schema 版本演进的业务文档；服务层在写入草稿或版本前必须执行完整 Schema 与业务规则校验，不能把 JSONB 当作无约束数据袋。

PostgreSQL 应用角色对职位需求版本仅有 `SELECT/INSERT` 权限，不得更新或删除；职位需求草稿和解析任务状态才允许受控更新。版本的不可变性由数据库权限与唯一约束共同保证，而不是只依赖 Python service 不调用更新语句。

职位需求草稿以 `editable`、`confirmed`、`replaced` 或 `abandoned` 标识生命周期；数据库部分唯一索引只允许同一租户与职位存在一个 `editable` 草稿。终态草稿保留历史身份，不会因新草稿创建而覆盖原行。

所有通过职位需求 Schema 校验的草稿 JSONB 在进入 `confirmed`、`replaced` 或 `abandoned` 后继续长期保留，包括模型初稿、成员修改事实、来源证据和冲突处理记录。90 天清理只作用于既定范围内的输入来源全文和加密原始响应，不清理结构化草稿结果、草稿身份或变更历史。

职位需求草稿执行显式 Schema 升级时，系统额外保留升级前的完整 JSONB 快照、确定性转换器版本和逐字段映射结果。无法无损转换的项目作为结构化待人工解决项保存在新草稿中并阻止确认；解决后形成的最终快照继续接受目标 Schema 的完整校验，原快照与转换事实不得覆盖或删除。
