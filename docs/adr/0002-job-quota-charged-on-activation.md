# 活跃职位额度在启用时占用，草稿不计额度

职位（Job）的 `active_jobs` 额度不在创建时占用，而在启用（draft/closed → active）时 `reserve→confirm`，关闭（active → closed）时 `vacate`；草稿创建与持有均不计额度、不设数量上限。这与企业的"创建即占 `companies` 额度"模式刻意不同：Issue #10 的验收标准把卡点定义在"达到活跃职位上限时不能**启用**更多职位"，产品语义上草稿是零成本的半成品，只有进入匹配可见的 active 状态才消耗套餐权益。被否决的备选是创建即占额度（与企业一致、可防草稿泛滥），代价是用户起草职位前就要关心配额，与"先写草稿再决定发布"的使用流程冲突。下游影响：`jobs.usage_reservation_id` 在创建时为空、启用时写入；关闭是退额度的唯一路径，因此关闭操作不设计为幂等（重复关闭返回 `job_status_conflict`），避免"额度是否已退"语义模糊。
