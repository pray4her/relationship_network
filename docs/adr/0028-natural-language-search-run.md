# 独立自然语言搜索是一段过程的不可变运行

租户成员提交搜索原句后，同一次执行完成搜索解释并调用检索底座，形成一条不可变的自然语言搜索运行；不存在「先检视再决定是否检索」的闸门。同一次结果展示实际采用的硬条件与研究主题查询，以及不参与检索的未支持条件。相较于两段过程（先解释、用户改条件再搜），一段过程把独立搜索保持为探索动作，而把有确认闸门的结构化需求留给职位需求版本。搜索解释不是职位需求草稿：无偏好条件、无来源冲突，目录内能执行的条件一律当硬条件，其余进未支持条件；研究主题查询可空，但硬条件与主题不可同时为空。搜索原句规范化后最长 4000 个 Unicode 字符，空或超限不创建运行；整份职位材料仍走职位需求解析。

运行先落库，在请求内做完，不是职位需求解析那种排队 SSE 任务。成功时对每条检索命中 get-or-create 本地人才，并冻结搜索命中快照（本地人才 ID、当时头部字段、数据版本、命中论文摘要、可选语义分）；重开运行看当时所见，人才详情看本地人才最新状态。失败进入可恢复终态，不得在原运行上重跑；显式重试是新运行。检索底座成功（含零命中）才确认一次 `searches` 额度；解释无效不记账；底座失败释放预占。客户端幂等键绑定规范化原句、LLM 配置版本与检索契约版本；同键同指纹回原运行，同键不同指纹 409。发起要 `search:run` 且租户可写，查看本租户运行要 `search:read`。结果始终脱敏，本切片不解锁联系方式。解释失败也计入与职位需求解析同类的技术限流，避免未扣额度的 LLM 成本被打穿。

**ADR 0021 中被 supersede 的条款**：配置版本只绑一条提示词和单一超时；最小能力探测只验证职位需求解析。配置版本改为按调用类型绑定提示词与超时，模型和隐私路由仍共享；搜索解释默认 15 秒（5–30 秒），职位需求解析仍 30–300 秒；探测必须覆盖所声明的全部调用类型，全部通过才启用。**ADR 0026 仍然有效**：本地人才只保存最新头部字段；自然语言搜索运行是与匹配运行、报告并列的快照消费者，不给本地人才做版本历史。

## Considered Options

- **两段过程（先展示解释再检索）**：被否。独立搜索不要检视闸门；采用/忽略在同一次结果里诚实展示即可。
- **复用职位需求草稿/版本**：被否。没有职位、不确认、不评分，偏好条件会静默不执行。
- **持久化异步任务 + SSE**：被否。与当场出结果的一段过程过远；运行记录仍是事实源，足以支撑超时后的可恢复失败与重试。
- **提交即扣额度，或有命中才扣**：被否。成功发起是一次有效检索，不是「找到了人」，也不是「模型看过原句」。
- **不新增权限、只认证即可搜**：被否。搜索消耗租户额度，必须有允许/拒绝用例。
- **失败运行同键自动重跑**：被否。运行不可变，重试必须是新运行。
