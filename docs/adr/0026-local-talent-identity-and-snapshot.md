# 本地人才是规范人物的稳定本地镜像，全局共享、仅同步写入

本产品为每一名规范人物建立唯一的本地人才记录，并以其本地 ID 作为租户人才、职位候选人与报告的引用主身份，而非直接沿用检索底座的规范人物 ID。相较于让业务对象直接引用规范人物 ID（上游标识变化会级联破坏历史引用），或在本产品内再次聚类合并（与检索底座职责重复、且缺少其论文与来源数据），本地人才只做身份稳定：与规范人物一一对应，去重与合并完全由检索底座的标识变化驱动；映射层保存当前与历史规范人物 ID 及全部历史来源 ID，任一外部标识重合即视为同一本地人才。

本地人才是全局共享表，不携带 `tenant_id`：所有认证用户只读，写入仅由同步路径在受限数据库角色下执行。租户级业务对象（租户人才、职位候选人、自然语言搜索运行、匹配运行、报告）仍按租户隔离。相较于为每个租户复制一份本地人才（违反「公共人才主身份不重复复制」，且把去重与合并放大到 N 份），这一第三类 RLS 姿态把共享主身份与租户业务关系分开，敏感门槛（联系方式、导出、搜索额度）由各自切片在租户侧另行施加。

本地人才只保存单一「最新已知状态」：头部字段快照、数据版本与最后同步时间，同步时 upsert，不保留版本历史，也不复制人物证据。历史不可变性由自然语言搜索运行、匹配运行与报告各自冻结的字段与证据快照承担，而非本地人才自身。相较于为本地人才维护版本化快照历史（在尚无消费者的 #13 就引入无谓的写放大与保留策略），或本地复制论文证据（证据体量无界且仅报告需要），这一取舍让本地人才在检索底座不可用时仍能以冻结字段展示「暂时不可用」，而引用有效性由稳定本地 ID 保证。

当检索底座合并两名规范人物时，同步路径检测到其外部标识重合于多个本地人才，即合并为一个：确定性选择最早本地 ID 为幸存者，重定向全部引用，并集全部外部标识，物理删除其余记录，并向只增的人才身份事件表写入合并事实。相较于软删除保留 `merged_into` 指针（引入本切片无消费者的状态），映射层并集保留的外部标识历史已足以在未来重建拆分，数据质量切片亦在此承接人工主身份与别名调和。
