# 每次 LLM 请求形成独立的只增调用记录

职位需求解析任务的每一次实际 OpenRouter 请求都形成一条独立、不可覆盖的 LLM 调用记录，自动重试、超时、限流、供应商错误和结构无效响应不会合并或覆盖；解析任务只聚合最终状态。相较于每个任务只保留一条最终记录，这一选择能完整核算所有尝试的模型、实际供应商、Token、成本和耗时，并还原失败与重试链路。

请求已发出但最终结果无法确认时，为该调用追加 `outcome_unknown` 结果事件。后续自动重试必须创建新的调用记录并关联前一次不确定调用，不覆盖其核心或事件，也不声称外部请求已经取消或去重；可能迟到的响应追加 `late_response` 结果事件，不改变已经由任务原子提交的业务结果。

保存 LLM 配置前的最小能力探测也必须形成独立调用记录。此类记录使用平台级 `config_probe` 调用类型，不关联租户或职位需求解析任务，并以候选配置指纹关联被探测的不可变参数；即使探测失败且没有创建正式配置版本，调用核心、原始响应保留边界和后续成本元数据仍按相同规则处理。

`config_probe` 调用关联长期保留的脱敏候选配置 JSONB 快照。快照不包含任何部署秘密，并作为只增审计事实受数据库不可变权限保护；其存在不表示该候选配置已经生效，也不能被后续成功配置覆盖。

LLM 审计数据拆分为四个边界：`llm_call_records` 在外部请求前保存不可变调用意图、尝试序号和输入/配置引用；`llm_call_outcome_events` 追加 `succeeded`、`failed`、`outcome_unknown`、`late_response` 等生命周期结果；`llm_call_metadata_events` 追加延迟到达的成本、Token 与实际供应商统计；`llm_raw_responses` 独立保存原始响应密文。调用核心、结果事件和元数据事件只允许插入与读取，原始响应表只允许受限保留期清理。

调用结果事件的状态机由数据库强制：每个调用首次只允许追加一个 `succeeded`、`failed` 或 `outcome_unknown`；只有已经存在 `outcome_unknown` 时才允许再追加一次 `late_response`。数据库拒绝重复首次结果、没有不确定结果的迟到响应，以及在 `succeeded` 或 `failed` 后改写业务结果；Token、成本和实际供应商等后续事实只能写入元数据事件。

租户解析调用与平台配置探测统一存入 `llm_call_records`，但由数据库检查约束强制作用域组合：`scope=tenant` 必须同时具有租户 ID 和职位需求解析任务 ID；`scope=platform` 必须没有租户或任务 ID，且调用类型只能为 `config_probe`。租户 RLS 只允许当前 `app.tenant_id` 读取或插入对应的 `tenant` 记录，绝不把空租户 ID 当作公共记录；平台管理员查看两类记录仍必须显式设置现有 `app.platform_admin` GUC。

`llm_call_outcome_events`、`llm_call_metadata_events` 和 `llm_raw_responses` 冗余保存父调用的 `scope` 与 `tenant_id`，并使用由作用域和租户 ID 生成的非空作用域键，与调用 ID 组成复合外键，强制平台空租户记录也必须和父调用一致。三张子表因此可在自身列上直接执行与父表相同的 RLS 策略并建立索引，不依赖应用层联表后再判断租户，也不允许子记录关联到不同作用域或租户的调用。

完整原始响应以应用层 AES-GCM 加密后保存在 `llm_raw_responses`，并记录调用记录引用、密钥版本、随机数和 90 天到期时间。到期清理任务删除原始响应密文及其解密材料，调用核心、元数据事件、错误分类和已经通过业务结构校验的结果继续保留；无效结构响应同样只能以密文形式短期保存。

AES-GCM 密钥通过 `RN_` 环境配置提供版本化密钥环，数据库只保存密钥版本 ID，不保存密钥或明文。轮换时新写入使用当前活动密钥，旧密钥至少保留到使用它加密的最后一份原始响应超过 90 天并完成清理；密钥、明文和完整密文不得进入应用日志或在线 LLM 配置。旧密钥缺失时记录平台诊断错误并拒绝解密，但不得回滚或改变已经完成的职位需求业务结果。

原始响应只能由平台管理员在后台解密查看，并沿用平台管理员必须启用 MFA 的全局入口门禁；查看操作不要求再次输入验证码，也不要求填写原因。每次查看写入平台审计记录，租户成员不能取得原始响应的密文或明文。

结构化响应已经通过业务校验时，成本、实际供应商或完整 Token 明细暂缺不阻止解析任务成功和职位需求草稿生成。后台按 generation ID 补齐统计并向 `llm_call_metadata_events` 追加结果；超过补齐期限仍不可用时追加 unavailable 事件。当前 `metadata_pending`、已补齐或 `metadata_unavailable` 状态由调用核心与最新事件推导，不回滚业务结果，也不为补元数据重复调用模型。

元数据补齐按调用作用域拆分执行路径。租户调用消息携带租户 ID 和调用 ID，普通 Worker 设置 `app.tenant_id` 后在 RLS 下处理；平台 `config_probe` 调用进入独立平台维护队列，由受限平台任务显式设置 `app.platform_admin` 并记录系统操作审计。普通租户 Worker 不得在同一个任务中切换到平台作用域。

LLM 调用记录禁止保存完整请求体、messages 或由模板与业务内容组装出的提示词，只保存职位需求输入快照引用、来源摘要、输入内容哈希与长度、提示词版本及哈希、结构 Schema 版本、模型参数和供应商请求标识。完整业务文本只存在职位需求输入快照中，调用记录通过不可变引用保持可追踪性。

租户界面只展示稳定的业务错误类别、可重试性和下一步操作，不透传 OpenRouter 原始错误、账户余额、供应商内部细节或请求报文。平台后台可查看详细错误码、供应商请求 ID 和各次尝试链路；需要查看加密原始响应时仍遵守单独的审计访问边界。

PostgreSQL 应用角色对 `llm_call_records`、`llm_call_outcome_events` 和 `llm_call_metadata_events` 仅有 `SELECT/INSERT` 权限，不得更新或删除；`llm_raw_responses` 的到期删除只能通过受限清理函数执行。不可变性由数据库权限保证，不只依赖服务层约定。

到期原始响应由独立数据库维护角色调用固定的批量清理函数处理，普通 API 角色和 Celery Worker 不具有 `DELETE` 权限。函数只允许删除 `expires_at <= now()` 的 `llm_raw_responses` 行并返回删除数量；维护角色不能借此任意查询、解密或删除未到期响应，也不获得对调用核心、结果事件和元数据事件的修改权限。
